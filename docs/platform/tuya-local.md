# นำเข้าอุปกรณ์ Tuya Wi‑Fi แบบ local (ไม่ใช้ Tuya Cloud ตอนใช้งาน)

อุปกรณ์ Tuya Wi‑Fi คุยกันในวง LAN ได้ด้วย **local key** ของแต่ละเครื่อง Aether Edge (โปรแกรมที่ติดตั้งบน Pi ในอาคาร) ใช้ key นี้ต่อกับอุปกรณ์โดยตรงทาง TCP 6668 แล้วส่งข้อมูลขึ้น Aether จึง **ไม่ต้องพึ่ง Tuya Cloud ตอนใช้งานเลย** ต้องใช้ cloud **ครั้งเดียว** ตอนดึง local key และตารางความหมายของ data point (DP) ของแต่ละรุ่นเข้ามา

ดูภาพรวมระบบ topic และสิทธิ์ได้ที่ [aether-edge.md](aether-edge.md)

## สิ่งที่ต้องเตรียม (ทำครั้งเดียว)

1. เพิ่มอุปกรณ์เข้าแอป **Smart Life** (หรือแอป Tuya) ตามปกติก่อน การเพิ่มอุปกรณ์ใหม่ Tuya บังคับให้ผ่านแอป
2. สมัครบัญชีนักพัฒนาฟรีที่ **https://platform.tuya.com** (Tuya IoT Platform)
3. เมนู **Cloud → Development → Create Cloud Project**
   - Industry: Smart Home, Development Method: Smart Home
   - **Data Center**: เลือกศูนย์ข้อมูลเดียวกับบัญชีแอป
     - บัญชี Smart Life ในไทยที่สร้างก่อนกลางปี 2025 ส่วนใหญ่อยู่ **Western America**
     - บัญชีใหม่อาจอยู่ **Singapore**
     - ถ้าเลือกผิด การนำเข้าจะ "ไม่พบอุปกรณ์" ให้ลองอีกศูนย์
4. ในโปรเจกต์ ให้เปิดใช้ (subscribe) บริการ **IoT Core** และ **Authorization** (แท็บ Service API)
5. แท็บ **Devices → Link Tuya App Account → Add App Account** แล้วเปิดแอป Smart Life ไปที่ **ฉัน (Me) → ไอคอนสแกน** สแกน QR ที่ขึ้นบนเว็บ
6. แท็บ **Overview** คัดลอก **Access ID/Client ID** และ **Access Secret/Client Secret**

## นำเข้าใน Aether

1. หน้า **เชื่อมต่ออุปกรณ์** เลือก gateway แบบ **Aether Edge** แล้วเปิด **นำเข้าจาก Tuya**
2. เลือก Data Center ให้ตรงกับข้อ 3 ใส่ Access ID และ Access Secret แล้วกดนำเข้า
3. ระบบทำงานเบื้องหลังไม่เกิน 90 วินาที:
   - ขอ token
   - ดึงรายการอุปกรณ์พร้อม local key
   - ดึงตาราง DP ของแต่ละรุ่น (ครั้งเดียวต่อรุ่น)
   - เข้ารหัส key แล้วบันทึก
4. ผลแสดงทุกเครื่อง พร้อม **ลายนิ้วมือของ key** (16 ตัวอักษร) แทนตัว key และบอกว่าใช้แบบ local ได้ไหม
   - **อุปกรณ์แบตเตอรี่** (เซนเซอร์ประตู อุณหภูมิ PIR ควัน ฯลฯ) หลับเกือบตลอด **ใช้แบบ local ไม่ได้** แนะนำใช้รุ่น Zigbee ผ่าน Zigbee2MQTT แทน
   - อุปกรณ์ Zigbee/BLE ที่ต่อผ่าน hub ของ Tuya (sub-device) ไม่รองรับทางนี้
5. ลงทะเบียนอุปกรณ์ที่ต้องการ Aether Edge จะเริ่มต่อกับเครื่องนั้นในรอบดึงค่าถัดไป (ไม่เกิน 30 วินาที)

**Access ID/Secret ไม่ถูกเก็บที่ใดเลย** ใช้แค่ระหว่างงานนำเข้า ไม่ลงฐานข้อมูล ไม่ลง log และไม่ถูกส่งกลับมาในหน้าเว็บ นำเข้าเสร็จแล้วจะลบ Cloud Project ทิ้งก็ได้ (แต่ถ้าจะนำเข้าใหม่ต้องสร้างใหม่)

## ข้อความผิดพลาดที่อาจเจอ

| ข้อความ | ความหมาย / วิธีแก้ |
|---|---|
| `tuya_auth_failed` | Access ID/Secret ผิด หรือเลือก Data Center ไม่ตรงกับโปรเจกต์ |
| `tuya_not_subscribed` | โปรเจกต์ยังไม่ได้เปิดใช้ IoT Core / Authorization หรือช่วงทดลองใช้หมดอายุ |
| `tuya_rate_limited` | ใช้โควตาการเรียก API ของบัญชีทดลองหมด รอแล้วลองใหม่ |
| `tuya_unreachable` / `tuya_timeout` | เซิร์ฟเวอร์ Aether ต่อ Tuya ไม่ได้ในเวลาที่กำหนด |
| "ไม่พบอุปกรณ์" (`no_devices_try_other_region`) | ยังไม่ได้ผูกบัญชีแอป (ข้อ 5) หรือเลือก Data Center ผิด ระบบแนะนำศูนย์อื่นให้ลอง |

## key เปลี่ยนเมื่อไหร่

**ลบอุปกรณ์ออกจากแอปแล้วเพิ่มใหม่ (pair ใหม่) = local key เปลี่ยน**
- Aether Edge จะต่อไม่ติด
- หน้าเว็บขึ้น "คีย์ไม่ตรง" (`key_rejected`) และคำสั่งไปยังเครื่องนั้นจะถูกปฏิเสธ
- ให้นำเข้าจาก Tuya อีกครั้ง key ใหม่จะแทนของเดิม
- ปุ่ม **ลืม key** ลบ key ของเครื่องนั้นออกทันที (Edge หยุดต่อในรอบถัดไป)

## ข้อจำกัดที่ควรรู้

- **Tuya IoT แบบทดลองใช้ (Trial) ห้ามใช้เชิงพาณิชย์** และหมดอายุเป็นช่วง ต่ออายุได้ผ่านแบบฟอร์มของ Tuya
  - ใช้เองในบ้าน/องค์กรตัวเองได้ตามเงื่อนไข
  - ถ้าให้บริการลูกค้า ต้องให้ลูกค้าสร้างโปรเจกต์เอง หรือใช้แพ็กเกจที่อนุญาต
  - การใช้งานประจำวันไม่แตะ cloud จึงไม่กระทบเมื่อ trial หมด มีผลแค่การนำเข้าใหม่
- **อุปกรณ์ส่วนใหญ่รับการเชื่อมต่อ local ได้ทีละ 1 ราย** ถ้า Home Assistant/LocalTuya ต่ออยู่ Aether Edge จะต่อไม่ได้ (สถานะ `busy`) ต้องปิดตัวอื่นก่อน ส่วนแอป Smart Life ยังใช้ผ่าน cloud ได้ตามปกติ
- Aether Edge ต้องอยู่วง LAN เดียวกับอุปกรณ์ เพราะหาอุปกรณ์จาก UDP broadcast ที่ข้าม VLAN ไม่ได้
